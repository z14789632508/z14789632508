# moyu

给 AI 加一些它缺的东西。

不是做大模型，是做那些**模型本身解决不了的小缺口**：

| 项目 | 缺口是什么 |
|---|---|
| **[ai-desktop-sense](https://github.com/z14789632508/ai-desktop-sense)** | AI 不知道你在干嘛——它只能等你开口 |
| **[mcp-mini](https://github.com/z14789632508/mcp-mini)** | 想让脚本调一次 MCP 工具，得背一整套 SDK |
| **[emotion-engine](https://github.com/z14789632508/emotion-engine)** | 你说"你现在很生气"，它还是客气地回你 |

三个都零依赖，都能直接塞进现有项目。

---

## 一点重复出现的事

做这些的时候，反复撞上同一个情况：

**你以为模型会做的事，它不做。**

```
你以为说"更生气一点"，它就会生气        → 不会，它客气地回你
你以为装了工具，它就会用                → 不会，它压根没想起来
你以为它记得上一轮说过什么              → 不记得
```

所以这三个项目其实是同一个思路：**别指望它，你自己加一层。**

```
告诉它"更生气"            → 没用
替它数，告诉它"5 档"       → 有用

给它一个工具              → 可能不用
把「什么时候该用」写进规则  → 会用

让它自己记住背景          → 会飘
把状态写进文件每次读       → 稳
```

---

## 三条共同原则

**① 状态放文件，不放上下文**

上下文会压缩、会长、会丢。一个 JSON 文件不会。

**② 输出具体指令，不输出形容词**

"说 8 句，一句一行" 比 "你现在很生气" 有用一百倍。

**③ 宁可少做一点，也别做假**

`ai-desktop-sense` 只读窗口标题不截屏——知道的信息少，但用得安心。
`emotion-engine` 只做纯规则——抓不到复杂语境，但成本是零、判断可解释。
